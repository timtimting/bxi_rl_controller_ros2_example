# 控制程序的 CPU 角色分配

这属于跨 Mod 的平台调度能力，在控制器公共框架实现；本次不涉及硬件节点或系统级 CPU 隔离。

## 默认分工

| 角色 | 执行内容 | 默认分配 |
| --- | --- | --- |
| `control` | 控制周期及同步策略／推理调用 | 容量最高的物理核中的一个逻辑 CPU；其他自动角色避开其全部 SMT 兄弟 |
| `communication` | 主线程、ROS 执行器工作线程、由主线程创建的 DDS 线程、未指定角色的 Mod 辅助节点 | 剩余容量最高的完整物理核，包含 SMT 兄弟；不强制使用能效核 |
| `compute` | Resource 加载线程及其创建的推理工作线程 | 排除控制／通信核心后，剩余容量最高的一组核心 |
| `background` | 维护线程、通信监测线程、托管子进程日志转发、Mod 生命周期工作线程的空闲基线 | 剩余较低容量核心；同构机器在资源允许时单独保留一个物理核 |
| `shared` | 显式选择宽 CPU 集合的扩展任务 | 所有允许 CPU，排除控制核及其 SMT 兄弟；可能与通信、推理和后台重叠 |
| `all` / `inherit` | 显式放宽限制或继承调用环境的兼容入口 | 不保证角色分离 |

这里的容量优先取 Linux `cpu_capacity`，缺失时回退到最高频率等现有探测信息。
控制核和通信核选定后，对剩余核心重新排序；稍低的睿频档位不会因此全部被排除在推理集合之外。

CPU 亲和性是线程属性。[Linux 线程创建规则](https://man7.org/linux/man-pages/man3/pthread_create.3.html)
规定新线程继承创建者的亲和性，因此主线程在导入 ROS／原生库之前就切换到 `communication`。
ROS 工作线程另外通过线程池 initializer 显式设置亲和性和普通调度策略，避免从其他角色提交任务时继承错误。
维护、监测和子进程日志转发线程也显式设置 `background`。
未显式设置角色的 Mod 辅助节点从原来的 `shared` 改为 `communication`；计算密集的进程节点可声明：

```yaml
scheduling:
  cpu_affinity: compute
```

该声明用于 `execution: process`。进程内节点的 ROS 回调共享框架执行器；其推理资源仍通过 Resource 路径创建。

## 分配示例与不足时的退化

| 拓扑 | control | communication | compute | background |
| --- | --- | --- | --- | --- |
| elf3-27，i7-1360P，4 个带 SMT 的性能核及 8 个单线程能效核 | 6，避让 7 | 4-5 | 0-3 | 8-15 |
| 4 小核＋4 大核的容量拓扑，大核编号 4-7 | 7 | 6 | 4-5 | 0-3 |
| 同构四核，编号 0-3 | 3 | 2 | 1 | 0 |

三个物理核时，后台与通信共享；两个物理核时，通信、推理与后台共享剩余核；
只有一个可用物理核时无法分离。所有集合仍受启动时允许的 CPU 范围限制，启动日志会列出 `role sharing`。
启动时的 `CPU affinity roles` 行给出完整计划；维护线程和监测线程还会记录实际亲和性。

## 影响与边界

- 性能核充足时，ROS 与推理工作线程不再共享同一物理核；推理可用核心数量也相应减少，
  不能保证总吞吐或最坏耗时必然改善。ONNX 的线程数、空转设置、本次均未调整。
- 控制线程仍同步参与推理。`compute` 不意味着所有模型运算都搬到独立线程，
  也没有改变 GIL、锁、QoS、控制周期或实时优先级。
- 后台归属只覆盖已有专用线程。同步 ROS 日志仍由调用它的线程输出，没有把所有日志改成异步写入。
- 显式指定 `shared`、`all`、`inherit` 或具体 CPU 可打破自动分离。尤其手动改变控制 CPU 时，
  其他自动角色不会随控制运行时的覆盖值重新规划；默认使用 `cpu_affinity: control`。
- 原生库若自行重绑线程或在别的线程里延迟创建工作线程，需要核对实际亲和性。
  当前保证的是本程序设置的基线与显式绑核，不是整个操作系统的独占或 IRQ 隔离。
- `CommunicationExecutor` 的线程池接入适配当前 Humble／Python 3.10；升级 rclpy 后应重新验证。

验证覆盖拓扑分配、少核退化、线程继承、三个执行器工作线程从控制 CPU 创建后重新绑到通信集合、
后台线程的真实 Linux 亲和性，以及独立 ROS Domain 中的 DDS／订阅／定时器工作线程。
不启动真实硬件，也不向电机话题发送命令。目标 ARM 真机尚未实测。
